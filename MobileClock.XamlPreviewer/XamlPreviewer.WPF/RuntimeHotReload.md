# Runtime Hot Reload

После первоначальной сборки XamlPreviewer сохранение XAML не запускает XamlCompiler или C++-сборку. WPF передаёт UTF-8-текст и путь файла в `mc_reload_markup`; разбор, проверка, bindings, коллекции и построение дерева выполняются в статической библиотеке XamlRuntime. Android продолжает создавать страницы из generated C++ XAML.

Поддерживаются стандартные элементы из ElementBuilder, статические атрибуты, опубликованные bindings и команды, Grid definitions, ListView.ItemTemplate, Storyboard и VisualStateManager.VisualStateGroups. Для bool-свойств доступен `Mode=TwoWay`, если registry публикует setter и target — `isOn`. По умолчанию writable bool на `isOn` также обновляет источник.

Новые поля ViewModel, типы элементов, native controls и обработчики анимаций требуют C++-сборки и явной регистрации. Ошибка содержит путь, строку и колонку; текущая страница и её подписки сохраняются до успешного построения замены.

## Использование

1. Один раз соберите XamlPreviewer и запустите его.
2. Выберите страницу приложения.
3. Измените и сохраните файл страницы либо используемого контрола во встроенном или внешнем редакторе.
4. Проверьте результат в UI. Ошибки отображаются в строке состояния, а последний рабочий UI остаётся доступным.

Watcher объединяет файловые события с задержкой 200 мс. Повторное событие для неизменённого текста не пересоздаёт дерево. Изменения сценария также не применяются повторно при каждом сохранении XAML.

## Native controls

InteractiveList и TimelineTabs публикуют runtime-адаптеры. При замене страницы существующие экземпляры сопоставляются по типу, `id` и порядку для безымянных экземпляров. Для нескольких экземпляров задавайте устойчивые уникальные `id`.

`InteractiveList.xaml` меняет содержимое существующего C++-контрола. Сохраняются remove handler, коллекция и active horizontal pan; scroll offset ограничивается новым допустимым диапазоном. В шаблоне сохраняйте native-контракты `interactiveListScrollViewer`, `interactiveListItems` и `interactiveListGestureTarget`. Item bindings проверяются даже при пустом Alarms.

## Проверка

Debug CMake-конфигурация desktop содержит цель `RuntimeMarkupTests`; тест запускается через CTest с именем `RuntimeMarkup`. Он использует реальные XAML страниц и контролов, проверяет rollback, повторные подписки, изменение коллекции, пустой item context, two-way bool, scroll и перенос pan при смене шаблона.

Реализация runtime-модуля находится в сабмодуле UtilityHelpersLib. При фиксации работы учитывайте изменения и новые файлы внутри этого сабмодуля вместе с изменениями приложения.
