# Глобальные пользовательские правила

- Когда пользователь пишет «залей ченжи», это означает только создать локальный Git-коммит с подходящим сообщением. Не выполнять `git push` и не отправлять изменения на удалённый репозиторий, если пользователь отдельно и явно не попросил это сделать.
- Не добавлять завершающий перевод строки после последней содержательной строки исходного или конфигурационного файла.
- Приватные поля и члены классов не используют префиксы или суффиксы; в методах класса к ним обращаются через `this->`.
- Реализации методов классов размещаются в `.cpp`, а не в заголовках, кроме шаблонных классов и шаблонных методов; парные геттеры и сеттеры располагаются рядом и отделяются от следующей пары пустой строкой.
- Секции класса всегда идут в порядке: `public` (константы, enum, вложенные классы, методы), затем `private` (константы, enum, вложенные классы, методы), затем отдельный `private` для членов класса.
- Список инициализации конструктора начинается с новой строки после сигнатуры конструктора; каждый инициализируемый член занимает отдельную строку, а запятая ставится в начале следующей строки.
- Свободные вспомогательные функции из `.cpp` размещаются в именованном namespace `_details` сразу после include-блока; безымянные namespace не используются.
- Условные операторы `if` и циклы всегда используют блочное тело на отдельных строках, даже для единственного выражения или `return`.
- Include-директивы располагаются тремя блоками: внешние библиотеки, файлы проекта, стандартная библиотека. Блоки разделяются пустой строкой; внутри блока пути сортируются по убыванию длины каждого сегмента пути, начиная с первого сегмента.
- Отступы в коде должны отражать каждый уровень области видимости: четыре пробела на уровень; вложенные `namespace`, блоки и тела функций получают дополнительный уровень отступа.
- В XAML с несколькими атрибутами первый атрибут остаётся на строке с именем элемента, а каждый следующий переносится на отдельную строку и выравнивается по началу первого атрибута.
